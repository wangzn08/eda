# V3 路径结构感知延时估算：方案冻结前记录

## 核心想法

V2 根据端点位置和端口查表。本轮额外利用官方架构图提供的三种路径约束：中央 Block 带可能需要绕行；互联端口的第一跳/最后一跳方向由 Net 模板规定；固定端点跳跃产生一个不能低于的曼哈顿行程下界。每个特征都由请求和官方 JSON 推出，运行时不读取答案或精确路径。参数仍只由固定开发集拟合。Marquardt 等（FPGA 2000）的位移延时表是快速估算基线，本轮在此基础上引入赛题特有的有向连线约束；最终方案尚不能称为全局最短路径算法。

## 离线真实路径核查

从开发集按曼哈顿距离确定性抽取600条：0–15有120条，16–63有160条，64–255有240条，256以上有80条。扩展压缩图精确求解器记录实际路程、Net跳数、长线跳数、转向和绕行。600条精确延时与公开答案全部相同，单线程进程CPU合计 **461.327秒**；作为十亿条常规求解方法不可行。

这600条是按距离分层的诊断样本，不代表官方请求分布。其中311条真实路线的几何行程超过两端曼哈顿距离；绕行超过10格的64条上，V2平均评分 **71.26**，低于零绕行组的 **82.88**。这支持研究绕行特征，但不证明端点几何能准确预测完整路线。详细统计见 [真实路径分析](V3-exact-route-analysis.json)。

最终阶段的验证输出 SHA-256 为 `c6e9068cfb5e8b8098f8257653e4317d5a9d84e02332de9162c489cef43c8a1e`，Python和 C++ 的150053条输出评分完全一致。相对误差 P50/P95/P99 为 **1.032% / 6.197% / 14.478%**。完整候选见 `V3-route-confidence.json`、`V3-route-momentum.json`、`V3-forced-route.json` 与 `V3-final-export.json`。曾试按原模型误差风险和交叉拟合收益分流，收益风险分流仅达到92.6100且选中约99%请求；未采用。长线周期位置特征同样无稳定收益。

候选结构与参数是在同一固定验证集上选出的，因此0.31188分是模型选择后的验证收益，不等于隐藏集收益。最终留出集尚未用于本轮调参。选择 `--algorithm v3-final` 后参数冻结；下一阶段只做一次最终留出评估和资源验收。

## 吞吐预检与采用条件

同机同一1000万条开发请求输入交替运行三轮，V2 进程CPU为1.921–1.946秒，V3最终候选为2.034–2.042秒，输出分别约403.33MB；记录见 [10M 对照](V3-timing-10m.json)。这是短批预检，不能替代十亿条完整输入输出的五轮实测。V3若在十亿条本机CPU只增加约10–15秒，则其准确率加权收益约0.2495综合分，预计高于时间扣分；正式结论必须以完整本机基准和最终留出数据计算。

验收顺序：先从冻结的源码构建并核对官方8条路径和开发600条精确结果，再做一次最终留出评估、五轮十亿条、可移植包独立编译。满足要求后才将V3设为默认并合入主分支；否则保留V2。官方评测机仍须另行验证。
