# V63：有真实路径证据的循环倍增跳转

24条开发路径逐段使用官方Arc/Net及architecture.move回放，全部延时一致。提取出的闭合端口循环可以重复，但几何位置会改变网线落点和附加延时。水平循环在1004个平移位置的采样中存在位移变化，故不能仅乘以名义跨度。

新实现src/repeat_cycle_jump.hpp在真实Graph.net_move结果上建立倍增表。每条记录包含最终站点和累计延时，若任一步不可达则整个组合不可达。32条长线闭合循环，6层（支持0至63次重复），表占92467200字节运行内存；由架构初始化生成，没有新增提交数据资产。该组件尚未整合到估算器，也尚未实测整个进程的峰值内存。

两组各100万次组件评估，与逐次真实网线移动零差异：

- 重复次数0至63：逐次CPU0.054981秒，倍增0.032024秒，约1.72倍；有效落点216656条。大量无效长跳不能被当作代表性请求。
- 重复次数0至7：逐次CPU0.006224秒，倍增0.014762秒；有效落点783371条，倍增反而更慢。

因此后续应根据循环长度选择逐次移动或倍增，且只有完整路径候选的构建开销确实下降时才整合。局部收益不能代表完整CSV吞吐，更不能证明十亿条达标。该结果也说明原来的循环迭代未必是主要耗时；入口/出口候选枚举和搜索状态数仍需优化。

文献方向延续V62的Botea与Harabor（ICAPS2013）压缩路径数据。倍增是常规组合技术，创新候选是将实际FPGA跨障碍移动与入口/转向/出口骨架组合；尚不作新颖性或效果的最终结论。
