# 架构驱动的可行路径组合与验证分迭代

## 当前范围

固定开发集 700,705 条用于拟合，固定验证集 150,053 条用于比较。未开展隐藏集评估、十亿请求测速或提交验收。V8 起点 95.041055；最终 C++ 验证分 **97.22350366143732**，核对结果由 V14-cpp-validation.json 记录。本报告中的数值是正延时评分，不是完全匹配率。

## 路线与参考

Marquardt–Betz–Rose 2000 的位移延时矩阵、Martin 等 2021 的学习延时预测、Botea–Harabor 2013 的压缩路径数据库，分别提供预处理、残差学习和压缩依据。

新增阅读 Petelin–Betz, *The Speed of Diversity: Exploring Complex FPGA Routing Topologies for the Global Metal Layer*, FPL 2016：[作者公开稿](https://www.eecg.utoronto.ca/~vaughn/papers/fpl2016_complex_routing.pdf)。其 II-D/IV-D 节通过参考导线的 Dijkstra 搜索构造按导线类型、方向与位移索引的前瞻表，支持我们关注连接拓扑与长导线入口。导线类型查表和架构自适应前瞻已有先例，不能作为原创。

本项目的创新候选是以下机制的联合设计：

1. 平移共享的逐端口局部路径及其足迹/总行程证书。
2. 多目标端口共享内部输入路径，再用官方 Arc 接到目标，扩大同一预算下的覆盖。
3. 少量入口路径、可重复长导线连接与尾部路径组合，按实际几何判断是否可行，产生跨较长距离的上界。
4. 把真实路径上界作为学习模型的信息，并在输出阶段强制满足该上界。

仍需系统检索与其他架构自适应前瞻、路径拼接和约束学习方法比较，不宣称算法首次提出。路径余量学习本身是残差学习；这里的余量指可行路径相对最短路的额外代价，与静态时序分析的 slack 含义不同。

## 为什么这些改动有依据

V9 误差分析发现普通区域贡献约 73.6% 的剩余失分，16–256 的中等距离区间也贡献大量失分。增加端口连接与有效位移特征，比只处理少量极端跨区请求更有希望。

官方长导线横向跨度为 10，纵向为 12。V10 用分方向位移余数、长导线入口与出口连接成本描述这一差异。放松空间限制后的端口图距离只作为特征，不冒充实际几何图的精确答案。

V11 从官方 Arc/Net 中识别可重复连接：输入端口经过 Arc 和长导线 Net 后回到同类输入端口。重复 q 次所需代价可直接相加；转向连接和尾部仍使用实际端口。经过 Block 的直线段拒绝，Gap 的代价按该直线段实际跨越次数加入。每条被接受的组合都是可行路径，因此提供上界，不保证全局最短。

最初组合只覆盖约 32.3% 的验证请求。调查发现很多短导线输入不能直接进入长导线。V13 从已有架构路径中为每个源端口/长导线输入组合选择最多四条低代价且位置有差异的入口路径，保留完整足迹证书。14,336 条记录约占 172,032 字节，将上界覆盖提高到 141,674 条，即约 94.4%。选择过程不读取 golden。

## 正确性与学习

设 D 为实际最短延时，U 为通过检查的组合路径代价，则 U≥D。对任意预测 P，min(P,U) 不会增大绝对或相对误差。当前验证集的 141,674 个有限上界均满足 U≥golden；这支持实现正确性，但有限样本检查不是所有请求的形式化证明。

V12/V14 比较两种训练方式：保留 V6 为预测基准并加入上界特征；或对存在上界的请求直接学习上界的剩余代价。所有标签拟合仅使用开发集。上界特征来源于架构路径，生成时使用固定大数作为搜索初始值，不使用模型预测或真实标签。验证集上反复选择模型仍有选择偏差，最终独立评估按当前优先级延后。

名为 nominal 的探索模式关闭部分几何检查，只能产生研究特征，不能作有效上界或直接截断预测；本轮正式比较和 C++ 高分候选使用带几何检查的模式。

## 存储与实现

- 目标共享路径范围20：原始 120,494,656 字节；逐目标平面的代价差分和足迹游程编码后 75,982,479 字节。启动时解码为 120,494,080 字节路径记录；30,123,520 条记录全部与原始表一致。
- 长导线尾部字典：11,969,216 字节。
- 入口路径银行：运行记录约 172 KB。
- V10 的树采用紧凑字节码，叶值保留 double；分支阈值取不大于原阈值的最大 float32，对 float32 输入保持分支语义。字节码 6,256,128 字节，C++ 输出已与 Python+独立上界逐条相同。V14 的具体字节码大小由其导出报告记录。

上述是组件大小，不是完整提交大小。当前研究源文件保留多个候选模型；之后需剔除未选模型并核算完整提交。没有制作提交包或进行验收。研究二进制路径文件仍需与对应官方架构配套，格式未包含架构指纹；部署阶段需要增加指纹校验。

研究代码已接入 estimate 的可选参数，V6 默认保留。V14 高分路线要求同时给出局部和长导线尾部文件。高分树模型目前仍用于准确性研究，未确认满足最终十亿请求吞吐要求。

## 下一步

达到97后继续向99推进，优先分析尚未压下的相对误差及未覆盖请求。候选包括更准确的长导线进出端口组合、跨特殊区域的可证明路径构造，以及把上界模型的学习规律压缩到更快的执行结构。每项必须保留验证消融、真实组件大小与适用边界；避免仅靠加树或扩大表推进。

## 最终核对与后续筛选

V14 的 150,053 条 C++ 预测与 Python 逐条相同，6593 条完全匹配。中位相对误差0.4259%，95分位2.2059%，99分位4.4917%；最大误差56.3131%，说明平均分改善后仍有少数难例。上界覆盖141,674条，未发现上界低于golden或预测超过有限上界的情况。
