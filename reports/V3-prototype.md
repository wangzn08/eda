# V3 原型：布线障碍特征与收益分流

## 假设

V2 的位置查表仍未显式描述两端之间可能绕过的中央 Block 带。先按官方架构 JSON 的 Block 几何，构造“横向是否经过 x=76–89、端点是否落在同一阻挡带、绕行到带边界的大致距离”三类路径草图特征。它不是最短路径，也不声称能确定实际经过的边。再用开发集的误差拟合轻量校正，并试验两种分流：按原模型误差风险，或按交叉拟合估计的新方法收益。

文献动机：Marquardt 等（FPGA 2000）使用位移延时表；本题官方 V0.3 的 Block/Line 规则提示几何上相近的请求可能有不同绕行成本。实现见 `scripts/experiment_route_confidence.py`，使用现有 V2 输出与固定开发/验证划分；不读取最终留出集。

## 验证结果

| 方法 | 验证评分 | 与 V2 差值 | 使用新校正的请求比例 |
|---|---:|---:|---:|
| V2 | 92.53153 | — | 0% |
| Block 路径草图×端口首字母×距离桶，统一校正 | 92.60463 | +0.07310 | 100% |
| 按开发集误差风险分流（阈值 0.01） | 92.58375 | +0.05222 | 63.87% |
| 按开发集双折交叉拟合的校正收益分流（阈值 0） | **92.61000** | **+0.07847** | 99.28% |

只按“V2 哪些请求难”分流，没有提高到统一校正之上；按交叉拟合的收益分流略好，但几乎所有请求仍需校正。长线周期位置特征没有稳定收益。这说明目前的路径草图太粗、分流无法节省大量计算。完整候选和阈值见 [机器可读结果](V3-route-confidence.json)。候选从同一验证集选出，0.078 分的提升需要在独立测试集复核，不能视为最终泛化收益。

## 决策与下一步

暂不改默认 V2，也不查看最终留出集调参。下一阶段应从精确参考求解器离线采集实际路径类别，研究可压缩的入口、长线使用和 Block 绕行信息，再训练“该用哪类路径信息”的收益模型。只有验证提升足以抵偿推理耗时、且独立留出评估和十亿请求全流程通过，才考虑升级正式算法。
