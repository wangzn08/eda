# 赛题一实施计划与阶段验收

目标：以官方 V0.3 规则和实际五份 JSON 为依据，完成可复现的 C++17 延时估算程序。采用“正确性基线 → 有依据的候选方案 → 独立留出评估 → 性能优化”的顺序。阶段未验收前，不把后续方法写成已确定方案。

## 官方约束与预算

- 输入 `From,To`，输出 `From,To,delay`；单位 ps。正式入口 `estimate -in ... -out ...`。
- 准确性：`100 * mean(1 - tanh(4 * abs(pred-golden)/golden))`。已目视核对 PDF 第 4 页的绝对值符号。golden=0 的评分规则未说明，单独报告，不自行代入除零公式。
- 总分：准确性×0.80 + 时间×0.15 + 一致性×0.05；时间分 `100*max(0,1-avg_cpu_seconds/1800)`。
- 单线程，内存不超过 2 GB；5 次运行任意一次超内存或超过 1 小时即无效；相同输入的输出须完全一致。
- 十亿请求的 30 分钟预算平均为 1.8 微秒/条，1 小时为 3.6 微秒/条，包含文件处理及被计入的初始化成本。本机测量不能代替评测服务器实测。
- 打榜数据由公开百万请求随机复制扩充；正式评测是非公开请求。将“新请求性能”和“重复请求性能”分别报告。推理程序禁止读取 golden 答案文件；缓存只可保存本程序计算的结果。
- 60,200 个 SRB × 496 端口 = 29,859,200 个理论节点。全量内部边为 493,158,400 条；每条即使只用 8 字节也需约 3.95 GB，尚未计索引。使用共享 Arc 模板与按坐标生成的 Net。

## 候选方法与决策顺序

| 候选 | 为什么考虑 | 必须先验证的条件 | 放弃/调整条件 |
|---|---|---|---|
| 共享模板和内部端口压缩 | 同一 SRB 的 8192 条 Arc 可复用；避免复制近 5 亿边 | 压缩保留查询端点、方向和距离，不能合并行为不同的总线位 | 与精确参考的任何距离差异 |
| 规则区域位移延时表 | FPGA 文献 R2 用 `(dx,dy)` 延时表降低查询成本 | 本题增加端口类型/方向状态；实际长线横向10、纵向12；跨 Gap 时位移不同 | 表太大，或边界/Block误差未被单独解释 |
| ALT地标下界与A* | R1 对有向图提供可证明的下界，适合加速精确回退 | 同时预存地标到节点和节点到地标的距离，正确处理不可达；计算实际空间 | 按约2986万节点、8地标、双向、4字节距离已约1.91GB，不能直接全节点套用；需压缩或少地标 |
| 分区入口/Transit Nodes | R5 通过入口距离与全局表减少查询搜索 | 建立覆盖正确性或明确近似边界；局部查询需单独处理；入口规模先测 | 跨分区边界状态过多，表规模超预算 |
| Contraction Hierarchies | R3 用捷径保留精确最短距离 | 小规模收缩实验量化捷径增长、节点排序和预处理成本 | 路网的低查询时间不能直接外推到 SRB；捷径膨胀即停止全图尝试 |
| Hub Labeling | R4 用标签交集回答精确距离 | 度量每节点标签数，估算完整大小，确认查询覆盖性质 | 标签内存不满足预算 |
| 轻量回归/残差校正 | R7/R8 给出 FPGA 特征设计案例 | 只使用 JSON 与请求能生成的特征；独立验证误差与微秒级推理成本 | 得分低于查表/几何方案，或不能泛化到留出区域 |

所有算法使用同一份连接语义。不得根据公开答案修改边权以“修复”样例。若最短路结果与 golden 不一致，先定位具体路径、坐标或文档歧义，再决定下一步。

P4 的第一项实验是量化可共享的端口行为和局部距离。即便仅给160×160对互联端口保存所有带符号位移，`239×1099×160×160×4` 也需约26.9GB，不能直接建立完整位移表。必须先证明某种状态压缩保距，或把查表明确作为近似模型并测量误差。R3–R6目前是候选阅读材料，在采用其实现前需通读算法正文、记录成立条件和本题适配方案，不依据摘要直接实现。

## 数据规则与待确认项

- O1 V0.3 第12–15页优先于较旧 DOCX 的示意错字。正式 JSON 的大小写和键名以文件本身为准，例如 `Inst`、`Port`、`Gap.Line`。
- 非可穿越方向：Block 占用坐标仍计入跨度；终点落入 Block 时断开。长线跨过 Block、终点落在真实 SRB 时，按文档示例仍可连通。
- 可穿越方向：Block 占用坐标不计入跨度，完整跨块收取一次相应附加延时。Line Gap 按实际几何路径穿越计费。
- 正式 Net 无 `delay` 键：普通 Net 基础延时按 0 处理，附加 Line/Block 延时；通过官方 Path 核对该解释。
- 未提供 Q&A：目标操作系统、CPU/编译器、能否携带架构/预计算资源、预处理是否计时、不可达请求输出格式、golden=0 处理均未完全明确。暂采用单一可执行文件内嵌架构、初始化计入本地测量；异常请求明确报错，不编造延时。

## 实验记录要求

每次记录：阶段、假设、引用、数据 SHA-256、代码版本/文件 SHA-256、命令、机器/编译器、样本选择、准确性得分、相对误差分位数、每条耗时分位数、端到端耗时、峰值 RSS、结论及下一步。运行生成物放 `out/`，可复跑脚本入 Git。原始数据保持不变。
